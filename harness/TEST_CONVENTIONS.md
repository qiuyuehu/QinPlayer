# QinPlayer 测试规范

> 创建：2026-07-01

---

## 一、命名规范

### 文件命名
- 测试文件：`<模块名>.test.ts` 或 `<模块名>.test.tsx`
- 放在 `tests/` 目录下
- 示例：`tests/lrcParser.test.ts`、`tests/colorExtract.test.ts`

### 用例命名
- 动词开头：`应该解析同时间戳双行歌词`、`过滤过亮的颜色`
- 中文描述，清晰表达预期行为

---

---

## 三、覆盖要求

### 必须测试
- 每个工具函数（`src/utils/` 下的所有模块）
- IPC 类型映射的完整性
- Zustand Store 的状态变更逻辑
- LRC 解析器的各种格式兼容
- 颜色提取的亮度过滤逻辑
- 时间格式化函数

### 可以不测试
- React 组件的渲染细节（留给主人手动验证 UI）
- Electron 主进程的窗口创建（需要真实 Electron 环境）
- Worker 线程的文件扫描（依赖文件系统）

---

## 四、运行方式

```bash
# 运行全部测试
vitest run

# 监听模式
vitest

# 运行指定文件
vitest run tests/lrcParser.test.ts
```

---

## 五、验收标准

- 全量测试通过（0 失败）
- 新增测试覆盖所有改动
- 不破坏现有测试
- 测试运行时间 < 30 秒

---

*测试是代码质量的最后一道防线。*
