# Devlog — 2026-07-09 窗口尺寸持久化 + 歌词行数修正

## 问题/目标
- 窗口每次启动都是固定 1000x680，用户希望记住位置和大小
- 单语歌词显示 6 行时，双语歌词也变成 6 行（应该保持 3 行）

## 方案审查过程
- v1：Codex 一审发现 6 个问题（迷你模式污染、bounds 校验太严格、createWindow 不需要 async 等）
- v2：Codex 二审发现 2 个 P1（进入 mini 前没保存 bounds、debounce timer 回调没检查 isMiniMode）
- v3：自审发现 3 个问题（"已写好"但文件已删、close handler 冲突、as any 类型粗糙）
- 最终方案经 3 轮审查后交给 Codex 执行

## 实现要点

### 窗口尺寸持久化
- 新增 `electron/windowBounds.ts`（152 行）：读写/验证/clamp bounds + 窗口状态
- `main.ts`：resize/move debounce 500ms + close 兜底保存，合并到现有 tray close handler
- `window.ts`：进入 mini 前 `saveCurrentWindowBoundsNow()` + 如果最大化先 unmaximize；退出时按 flag 恢复
- `normalizeWindowBounds`：clamp 最小尺寸 → 找有效显示器（标题栏至少 60px 可见）→ clamp x/y
- 最大化/最小化状态单独保存（`windowState` key），启动时恢复
- macOS activate 修复：模块级 `currentFeatureFlags` 变量
- DB 异常保护：所有 getDatabase() 调用都有 try/catch

### 歌词行数修正（待实现）
- `LyricsPanel.tsx`：`lyrics.some(line => !!line.translation)` 检测单语/双语
- 单语用 `lyricsMoreLines` flag（6行/3行），双语保持 3 行
- opacity 计算基于 `Math.abs(distance)`，自适应无需改动

## 踩坑记录
- WSL 下 node_modules 的 rolldown 原生绑定缺失（只有 win32），需要 `npm install @rolldown/binding-linux-x64-gnu --no-save`
- 方案写完不能顺手写代码（windowBounds.ts 被主人要求删除让 Codex 重写）
- debounce timer 回调必须二次检查 isMiniMode（用户拖动窗口 → timer 排队 → 进入 mini → timer 触发 → 保存迷你尺寸）
