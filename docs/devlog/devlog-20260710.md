## 实现要点

### harness/checks.js
- TypeScript AST 约束检查，使用 `ts.createProgram()` 读取 tsconfig
- 导出 `runChecks()` 函数（供测试调用），CLI 入口只设置 `process.exitCode`
- 扫描文件数按作用域检查：electron/、electron/workers/、src/ 分别必须命中
- 合并两个 tsconfig 时按绝对路径去重
- 白名单按 `rule + file + AST 表达式` 匹配，不按行号
- 过期白名单报错

### 检查项（P0 实现）
1. **主进程禁止同步 I/O** — 追踪来自 `fs`/`node:fs` 的所有 `*Sync` 调用
2. **Worker 禁止导入数据库模块** — 检查 `electron/workers/` 目录下是否导入数据库模块

### 白名单机制
- 5 条历史同步 I/O 调用（main.ts 的 existsSync、window.ts 的 existsSync/unlinkSync x2）
- 每条必须附带 `pattern` 和 `reason`
- 新代码不允许加入白名单

### npm 脚本
- `pretest`：`npm test` 前自动运行约束检查
- `verify`：约束检查 + 构建 + 测试

### 文档更新
- CONSTRAINTS.md：歌词滚动改为 scrollTo()
- DECISIONS.md：新增 2026-07-10 决策，旧决策状态更新
- SPEC.md：歌词滚动方式同步更新
- harness/SPEC.md：目录结构更新
